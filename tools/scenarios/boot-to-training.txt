# Boot to Training Mode on Final Destination: from a freshly launched training
# build to the in-stage state, with both fighters on stage. Reusable prefix:
# `include` it from drill scenarios. Player is Ness (character select cursor
# position, see below); the CPU opponent keeps whatever character Training's
# character select gives it by default.
#
# Timing is frame-exact (movie frames from power-on, fast disc loads; see
# docs/developer-workflow.md); the frame numbers in the comments are where
# each step starts. Presses are 2 frames. Where a press or a cursor clamp
# waits on a load, it has about 10 frames or more of margin past what was
# measured on the developer's Dolphin, so a training-build change that makes
# a load slightly longer doesn't desync the movie.
#  - Cursors (character select hand, stage select crosshair) accelerate with
#    how long the stick is held, so a move is "clamp to a screen corner, let
#    go for a few frames, then hold one direction for a fixed number of
#    frames". Same frames, same place, every run. A clamp may start before
#    the screen reads input: it only has to end in the corner.
#  - The scenario assumes a save with every character and stage unlocked (the
#    stage select layout and the icon positions below depend on it).
# 581 frames of movie: Training is reached about 12.5 s after Dolphin launch
# (measured times: docs/developer-workflow.md).
